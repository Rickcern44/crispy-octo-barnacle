# Spikes

This folder holds bounded investigations supporting the
[SDD Lite Improvement Plan](../SDD_LITE_IMPROVEMENT_PLAN.md).

A spike answers a specific design question before implementation. Keep its result
compact and distinguish recommendations from approved decisions.

Use descriptive filenames such as `001-revision-and-criterion-identity.md`.
Each spike should contain:

- Question and why it matters.
- Scope and time or effort bound.
- Options considered and repository evidence.
- Experiment or prototype results, when needed.
- Recommendation, tradeoffs, and unresolved decisions.
- Effect on the improvement plan and proposed next step.

Spike conclusions are provisional until accepted. Do not include raw transcripts,
hidden reasoning, or production state dumps.
